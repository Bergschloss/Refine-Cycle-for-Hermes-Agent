# SPEC — Release Acceptance Criteria & Usefulness Verification for Refine-Cycle

**Plugin Target:** Refine-Cycle `0.14.2+`  
**Host Systems:** Hermes Agent v2026.8.31+ (Linux server `92.5.18.124` & Windows 11 desktop)  
**Corpus Sources:** `G:\Claude\cc-corpus.db` (125 sessions, 38k messages), live server `state.db`  

---

## 1. Executive Summary & Goal

A self-refining agent plugin must satisfy two equal, opposing imperatives:
1. **Safety (Negative Gate):** It must NEVER write garbage, hallucinations, developer-test artifacts, unbacked single-occurrence noise, duplicate rules, or malicious external prompt injections into the agent's future context.
2. **Usefulness (Positive Gate):** When the agent experiences genuine, chronic, recurring tool/execution failures across multiple sessions, the plugin MUST propose and apply concrete, actionable, high-quality memory or skills that permanently eliminate or mitigate that failure.

Previous iterations solved the Safety Gate (noise was blocked, `applied=0`). This specification defines the final release requirements and the empirical verification pipeline to prove both Safety and Usefulness.

---

## 2. The 4 Mandatory Release Gates

### Gate 1: Safety & Architectural Invariants (Zero Tolerance)
| № | Invariant | Verification Mechanism | Status Standard |
|---|---|---|---|
| **I1** | **No Delete Proposals** | Proposer schema and validator reject `action: delete`. Only rollback may delete. | Enforced in `llm.py` & `core.py`. |
| **I2** | **`state.db` Read-Only** | Every connection string has `?mode=ro` or uses `sqlite3.connect(..., uri=True)`. | Enforced across codebase. |
| **I3** | **System Prompt Immutability** | Base prompt is untouched; only `skills/`, `prompt_notes.json`, and `MEMORY.md` may be modified. | Enforced in `core.py`. |
| **I4** | **Database Egress Scrubbing** | Credentials scrubbed at `_evidence_text_or_none` before reaching LLM or journal. | Single choke point enforced. |
| **I5** | **Pre-Edit Backup & Rollback** | Atomic backup before any file mutation; rollback restores byte-for-byte. | Verified via `journal.py`. |
| **I6** | **Daily Edit Budget (3/day)** | Strict rate limiter with concurrency locks; releases slot on failure. | Concurrency tests passing. |
| **I7** | **Standard Library Only** | Python 3 stdlib only; cross-platform path resolution via `config.hermes_home()`. | No external dependencies. |

---

### Gate 2: Garbage & Noise Elimination (Negative Verification)
A candidate failure pattern must be rejected immediately without calling the LLM or writing edits if:
1. **Dev / Test Noise:** Contains paths like `scratch/refine-synth-*` or names `tests.run_tests`, `unittest`, or internal test harness errors.
2. **Thin Evidence:** `sessions_seen < 2` AND `count < 5`. Single-occurrence failures are discarded.
3. **Duplicate / Already Covered:** The underlying `pattern_fingerprint` is already addressed by an active prompt note or memory entry.
4. **Clean Session:** Sessions with normal execution or self-correcting errors must yield a clean `no_op` or `no_applicable_pattern`.

---

### Gate 3: Empirical Usefulness Standard (Positive Verification)
When fed real recurrent failure clusters (from `cc-corpus.db` or live sessions), the proposal generated by the LLM must satisfy the **5 Quality Principles**:

1. **Grounded:** The proposal directly addresses the specific failure mode observed in the tool outputs (e.g. bash quoting errors, missing API permissions, tool parameter mismatch).
2. **Specific:** Contains precise trigger conditions and clear corrective steps, rather than vague platitudes.
3. **Action-Altering:** A future agent following this rule would execute tools differently and avoid the error.
4. **Non-Trivial & Uncovered:** Does not simply restate an invariant or system instruction; does not use robotic bypasses (e.g. "ask for clarification" for non-interactive commands).
5. **Compliant with Bounds:**
   - Prompt note: $\le 120$ characters target ($\le 200$ ceiling), allowlisted action.
   - Memory: $\le 200$ characters target ($\le 500$ ceiling), category and reason grounded.
   - Skill: Valid frontmatter, clean instructions, passes syntax check.

---

### Gate 4: Observability & Distinguishable Outcomes
Every execution of Refine must result in an unambiguous, queryable outcome in `refine_journal.jsonl` and `/refine audit`:
- `applied`: Edit successfully staged/applied with backup and ledger tracking.
- `no_applicable_pattern`: No pattern passed the recurrence/safety bar (LLM not called).
- `no_op`: Pattern evaluated by LLM, but deemed transient or already handled.
- `reviewer_only`: Discovered via reviewer path; journaled for human inspection, not auto-applied.
- `duplicate`: Pattern already addressed by active rule.
- `daily_limit_reached`: Budget ceiling reached cleanly without state corruption.

---

## 3. Empirical Test Protocol on `cc-corpus.db`

To verify Gate 3 against real historical dialogues:
1. Extract top recurrent failure clusters from `G:\Claude\cc-corpus.db` meeting `sessions_seen >= 2`.
2. Construct isolated replay contexts for the top 3 failure categories:
   - **Case A (Bash Quoting / Syntax):** `unexpected EOF while looking for matching '"'`.
   - **Case B (MCP Auth / Permission):** `Permission Denied: Resource not accessible by personal access token`.
   - **Case C (Tool Timeout / Process Control):** MCP timeouts or process limits.
3. Run the proposer model (`gpt-5.6-luna-900k` on server or Hermes LLM route) against each case.
4. Grade each proposal against the 5 Quality Principles.
5. Verify dry-run application, journal logging, and rollback mechanics.


## 0.14.4 release clarification

The production default is **3 edits per day**. Controlled test and corpus-replay
configuration may explicitly select a higher limit (for example, 10); Refine must
honour that operator-selected value and must not clamp it to the production default.

Rollback is deliberately an explicit human command, not a model tool. Verify a
successful lifecycle through the command registered by Hermes: `/<resolved-command-name>
rollback <journal_id>` (or in-process with `_handle_refine_command("rollback <journal_id>")`).
When Hermes owns `/refine`, the plugin's resolved command is `/refine-cycle`.
